Research · first study

I gave a frontier agent a guide to my local tool. It used more model work, not less.

I expected that an AI agent, handed Tables and a short guide to using it, would turn a picture of a table into a CSV with less model work than reading the picture itself. On seven small tables it did not.

Exploratory · run 19 September 2026 Outcome: no advantage

The idea was tested and these inputs did not support it. There is no agent skill or guide to install. Tables remains a tool for a person who checks the result. This study says nothing about that use.

The question

Does an agent reach the same checked CSV with less model work when it is given Tables and a guide to it? I asked Claude Code for a CSV of one table image, three ways:

  1. Normal. The request alone, with the agent’s usual tools.
  2. One-line instruction. The same request plus “Complete the task with as little model work as practical.”
  3. Guide and Tables. The same request plus my guide and a working copy of the Tables reader.
How the test was set up
  • Agent: Claude Code 2.1.278 in headless mode with the model claude-fable-5-1, on an Apple M1 Pro with 32 GB of memory and macOS 27.0.
  • Inputs: seven invented table images, five rendered and two photographed, fixed before the pass. My own tables were not used.
  • One fresh session for each image in each of three arms, 21 sessions in total. Every arm had the same tools: a shell and local files, with web tools and connected services off.
  • Each session ran in a new folder outside the repository holding only the image under a neutral name. The guide arm had a minimal copy of Tables with no test files, expected answers or other documents.
  • Each saved CSV was compared with answers written before any run, for whole-table equality and for exact cells. No person reviewed any output.

What happened

The guide arm recorded more output tokens, more cached input, more turns and more time than the normal agent, and one fewer exact table. The one-line instruction was the cheapest of the three at the same exactness as normal.

Every normal and one-line session read the image with the model’s own vision and wrote the file. Every guide session ran the Tables reader, wrote its rows out unaltered and reported an unreviewed draft. Six of the seven guide sessions never opened the image.

The one inexact table is the reader’s known extra empty row on a table without ruling lines, shown on the Tables page. The agent kept the row, as the guide requires, and told the person to check it. The normal agent read the same image exactly.

About 70,000 cached input tokens were present in every session before any work on the table. Differences between the arms are small beside that fixed amount.

A token budget for one table

The normal arm is also a record of what asking a frontier agent costs for this task. Running the local reader directly uses none of it. On these seven images the reader gave the same cells: 125 of 125, and 6 of 7 whole tables.

The wording this supports: no remote inference was required for these tested executions, at the same cell exactness, where the normal agent route recorded the model demand above. That is a token budget for this task: roughly what one small table costs if the alternative is asking Claude Code.

Limits on that wording

  • It is demand that could be avoided, not a reduction anyone made. Nobody was observed using an agent for this task beforehand. If the alternative is typing the table by hand, there were no tokens to begin with.
  • Nearly all the input tokens are Claude Code’s fixed context, not work on the table. They describe this agent and this configuration. A bare model call with one image was not measured and would be far smaller.
  • The one-line instruction lowered the agent’s own figure, to a mean of 399 output tokens per table.
  • The local route is not free. It needs a 366 MB runtime set up once, and about a second of local processing for each table.
  • Coverage differs on real inputs. The reader refused three of my twelve real tables, so a budget counted only on tables it can read would overstate the benefit.
  • Tokens are model demand, not energy.

Not measured and not established

  • Energy use, or any reduction in it.
  • Behaviour on unfamiliar, large, dense or real tables. All seven images were development examples: the reader was built against them, and the same person wrote them and their answers.
  • Other agents or models, or a session with less fixed context.
  • Variation between repeated runs. There was one pass.
  • Whether a shorter guide would do better.

This was a development check on seven authored examples with one agent. It is not a reliability claim in either direction. For a twelve-cell table, reading the image costs the model little, while the guide adds its own text, a tool result and a longer report. That may change on much larger tables. It was not tested.

Decision

Narrow. I have retired the claim that Tables and this guide reduce an agent’s model work on small clean tables. The guide stays as documentation of the reader’s command-line use, unchanged. If the question continues, the one next question is whether the comparison changes on larger tables that were not used in development. That has not been started.
