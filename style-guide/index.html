Principles

Start with the task

Say what the person can finish. Name any models and their jobs separately, where people can inspect them.

Make work explicit

Picking a file doesn't start processing it. Label the button that starts work, show progress and offer Stop whenever cancellation works.

Keep the source close

Put the original beside the draft. Let people fix values and keep empty cells empty instead of filling gaps with guesses.

Review before saving

Make review an explicit step. Editing a reviewed draft clears its review state before you can export again.

Keep local operation, setup downloads and any configured source fetching explained separately, stating what the tool actually reads and writes.

Marks and motion

The kttl wordmark and geometric cup identify the app. Keep icons secondary to visible labels. The header above uses the site's lockup at 40px high.

Colour

Navy text on pale blue and white, with one blue for actions. Swatches come from tokens.json, which npm run patterns:check checks against the theme.

  • Ground #edf2f7 · $k-ground App background: pale blue.
  • Paper #ffffff · $k-paper Cards and working surfaces.
  • Ink #16335b · $k-ink Navy: all primary text and dark chrome.
  • Grey #54677f · $k-grey The single grey step for secondary text, AA on ground and paper.
  • Rule #c9d3e0 · $k-rule Hairline rules only, never text.
  • Interactive #2f6fd0 · $k-interactive Primary buttons and focus.
  • Interactive text #1d55b0 · $k-interactive-text The same blue, dark enough for AA link text.
  • Tint #e0eafa · $k-tint Tinted pills: tags and quiet notices.
  • Highlight #00e5e5 · $k-highlight Cyan, only on navy: the privacy rule, the lockup rule and steam.
  • Border soft #d7e0ec · $k-border-soft Card border, between paper and rule.
  • Ink muted #bfd2ea · $k-ink-muted Muted copy on navy.
  • Error #b02a2a · $k-error GOV.UK error treatment.
  • Success #1c7a4f · $k-success Status: a claim proven.
  • Pending ink #7a3c1c · $k-pending-ink Status: measured but not settled (GOV.UK Frontend 6.4.0's orange tag), on pending-tint.
  • Pending tint #fde4d7 · $k-pending-tint Ground for pending-ink.
  • Mark #ffdd00 GOV.UK mark: matched words in read text (Share Copy, Label). Not a theme setting; carried as each tool's own style.
  • Mark ink #0b0c0c Text on mark.
Colour supports words — use labels like "Needs review" or "Could not read the image". Keep cyan on navy and use the grey token for muted text instead of dropping opacity.

Errors use GOV.UK error styling ($k-error: #b02a2a), alongside success and pending colours for evidence states. Flagging a cell to review isn't automatically an error or a confidence score.

Typography

System fonts only: system-ui, -apple-system, "Segoe UI", Helvetica, Arial, sans-serif, with monospace for filenames, timings and raw values. No web fonts to download.

File selection and correction

Use the file-picker pattern: a real labelled file input with an optional drop target. State accepted formats and size limits, and keep previews, validation and unsaved-work checks inside the tool.

Give editable fields visible labels or precise accessible names (like row and column coordinates). Put errors near the field, summarise failures at the top, and keep the original visible while editing.

Voice

Plain British English. Lead with the person's task, say what an action will do, and keep drafts clearly distinct from reviewed results.

Actions
"Read this table", "Stop", "Save reviewed CSV". Use verb + object where it makes the action clearer.
Uncertainty
"Check this cell against the image." Say what needs attention; don't invent a confidence score.
Failures
Say what broke, what happened to the person's work and what they can try next. Only promise their work is safe when that's actually true.
Models
Name active models, their jobs and exact sources. A tool without a model says "Models used: none".

Accessibility

GOV.UK gives a solid base, though Kettle's own adaptations and full flows still need testing.

  • Every control, disclosure, file picker and edit field must work by keyboard, with visible focus landing somewhere sensible after actions.
  • Focus uses a 3px blue outline, 2px offset and white inner edge so it stays clear on navy.
  • Associate labels, hints and errors with their inputs. Never rely on colour, icons or motion alone.
  • Announce live status changes politely and expose failures to assistive tech (static specimens don't need live regions).
  • Check zoom, narrow windows, reduced motion and forced colours. Keep hit targets at least 44px; long filenames and wide tables shouldn't blow out page width.
  • Check contrast on real surfaces — hover, focus, disabled and error states — rather than assuming overrides inherit GOV.UK contrast.

iPhone and iPad

Kettle Cups for iOS uses the same theme in SwiftUI, reading its own copy of tokens.json checked by unit tests. Everything above applies except where iOS conventions differ:

tiny12.5–12.8pxcaption
  • Dynamic Type replaces the fluid scale, tracking the user's iOS text size just as rem follows browser settings. Spacing uses the smaller end of the scale, in points.
  • Light mode only, matching the desktop app.
  • The header keeps the wordmark, Cup name under a cyan rule and "Nothing leaves this device." The system back button stays on a navy bar so swipe-back works.
  • Photos instead of files. Camera and photo picker replace the file picker, still stating what's accepted and that it stays on the phone.
  • Tags reuse the same palette plus green for passed checks and light-on-ink for firm findings or failures. Every status is still a word.
  • No hover or focus rings. Pressed states darken instead. VoiceOver and Dynamic Type are the accessibility checks that matter on iOS.
