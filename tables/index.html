What happens

  1. Choose an image. One still JPEG, PNG or WebP, up to 15 MB and 25 million pixels. Rotate in 90° steps and trim the edges so only the table remains. The preview shows exactly what will be read.
  2. Read it. The reader finds the table structure and the text in each cell on your CPU. It refuses merged or irregular cells rather than flattening them, and shows an error you can retry.
  3. Check every cell. The draft grid sits beside the image. Every cell is an editable field. Cells the reader moved during alignment are marked Check text position, which describes changed placement, not confidence. Add or remove rows and columns if the structure is wrong.
  4. Tick and save. Any edit clears the review checkbox. Once you tick that you have checked every cell, save as CSV. Every cell is quoted, empty cells stay empty, and text that could act as a spreadsheet formula gets a leading apostrophe.

Which tables to start with

Start with a clear, upright, tightly cropped image of one printed table in English, with no merged cells. Two cropped phone photographs of printed examples were read correctly in the latest check. Handwriting, strong tilt, blur, small type, spanning headings and larger layouts remain unproven. The reader can miss spaces, misread numbers or add empty rows, and a wrong layout can still look rectangular, so every cell needs checking, marked or not.

Limits of the reader and the review

The reader is limited to 180 seconds, and the draft to 100 rows, 20 columns and 2,000 characters per cell. Alignment orders recognised fragments within a cell, joins them with spaces and trims outer whitespace. Text whose centre is above or below the detected table is excluded, so a mistaken table boundary can omit source content.

Rotation and cropping help locate the table; they do not establish that its cells are correct. Cropped images are prepared as PNG in browser memory and the original file is unchanged.

There is no result history. Clearing removes the in-memory grid and image. A CSV you download remains wherever your browser saves it.

Models used

Tables uses four specialist models from PaddleOCR, packaged by RapidAI. All four run locally on your computer’s CPU.

SLANet-plus
Finds the table’s rows, columns and cell structure.
PP-OCRv4 mobile text detector
Finds regions of text in the image.
PP-OCRv6 small multilingual text recogniser
Reads the characters in each text region.
PP-OCR mobile v2.0 orientation classifier
Checks the orientation of text before recognition.

The four model files total about 34 MB. RapidTable 3.0.2 and RapidOCR 3.9.2 run them. Setup downloads and verifies the files; normal use downloads nothing.
